# ADR-0002: TLS bridge контроллера

- Статус: принято для реализации; совместимость с движком не проверена (M2)
- Задачи: RH-012, RH-013

## Решение

- Rustls 0.23 через `tokio-rustls` 0.26, crypto provider `ring` задан явно
  (`builder_with_provider`). Протоколы — безопасные версии по умолчанию (TLS 1.2/1.3).
- Trust roots: `webpki-roots` (корни Mozilla, поставляемые с библиотекой). Сертификаты Tailscale
  Serve выпускает Let's Encrypt. Собственного verifier и режима «принять любой сертификат» нет.
- `enable_early_data = false`: без 0-RTT.
- Порядок без deadlock (план 7.2.1): сначала TCP+TLS к фиксированному target и полная проверка,
  потом `127.0.0.1:0` listener. Первое принятое соединение связывается с уже проверенным каналом.
  Каждое следующее соединение движка получает свой TLS-канал к тому же target. Пока этот канал не
  проверен, байты движка не читаются.
- Лимиты из плана 7.5: connect 8 с, handshake 8 с, подготовка 15 с, 4 sockets на сессию, буфер
  256 KiB на направление (`copy_bidirectional_with_sizes`, естественный backpressure).
  Idle timeout для работающей сессии нет.
- Ошибки: `TLS_NAME_MISMATCH`, `TLS_CERTIFICATE_EXPIRED`, `TLS_CERTIFICATE_INVALID`,
  `TLS_HANDSHAKE_FAILED`, `ENDPOINT_UNREACHABLE`. Raw TCP к target bridge не открывает ни при какой
  ошибке.
- Конструктор с произвольными trust roots — приватный (`Target::new`). Тесты используют его со
  сгенерированной в памяти тестовой CA. Публичный API (`TlsBridge::open`) принимает только
  `RemoteEndpoint` и штатные корни.
- `RemoteEndpoint` принимает только IPv4 из `100.64.0.0/10`, порт `21118` и полное имя
  `*.<tailnet>.ts.net`. Проверка диапазона — это проверка формата, а не удостоверение личности.
  Личность подтверждает сертификат.

## Открытые вопросы (M2)

- Сколько sockets реально открывает движок за сессию, совпадает ли это с лимитом 4.
- Таймеры handshake/heartbeat upstream относительно таймаута подготовки.
- Как запретить upstream сохранять пароль под адресом `127.0.0.1:<port>`.
